    From an idea to a phone call

    The same four steps as the commercial platforms, each one a screen in the console.

      What it does

      ◆

      Visual flow builder

      Steps that talk and collect fields, tools, transfers and global rules. Code moves between steps; the LLM only talks inside one.

      ☏

      Phone numbers

      Inbound and outbound calls over LiveKit SIP trunks, voicemail detection, transfer to a person, the caller's number in the flow.

      ⇶

      Campaigns

      A CSV of contacts, calling windows in their time zone, a limit on calls at once, retries, consent and opt-outs.

      ✎

      Post-call analysis

      Summary, success by the agent's own rule, sentiment, custom fields and a QA score, checked against real transcripts.

      $

      Cost and latency per call

      Tokens, speech seconds and characters priced per call; reply delay per turn; a dashboard of outcomes and success.

      ⇄

      Integrations

      Books into each doctor's Cal.com calendar during the call; sends results to signed webhooks, Slack, HubSpot and Google Sheets.

      How a call runs

      • An agent is data, not code. The runtime loads instructions, voice and the published flow from the API when a call starts.
      • The API never sits in the audio path. Audio goes browser or phone ⇄ LiveKit ⇄ runtime; the API is asked only at start, end and for tools.
      • One process per call. Speech-to-text, the LLM and the voice all stream, so the agent starts speaking before it has finished writing.
      • Slow work runs in a worker. Document ingestion, the campaign dialler, post-call analysis and after-call deliveries are background jobs.

      What broke in real calls, and the fix

      Every one of these was found by calling the agent, not by reading the code.

      "Afternoon" booked at noon

      The time parser matched "noon" inside "afternoon". Word boundaries fixed it, and a test case keeps it fixed.

      Phone calls dropped after 20 seconds

      The softphone offered encrypted media that the SIP trunk refused. Allowing SRTP on both trunks fixed inbound and outbound.

      A voicemail greeting taken for a person

      "Hi, you've reached Rohan" sounded human to the detector. Examples of voicemail openings in its prompt fixed it.

      Cal.com refused the booking

      It rejects attendee emails that cannot receive mail. Callers rarely give one, so bookings now use the clinic's own address.

      Run it yourself

      Docker Compose starts the API, worker, runtime, console, Postgres, Redis and storage. Media goes through LiveKit Cloud's free plan.

      cp .env.example .env.local   # LiveKit, OpenAI, Deepgram keys
docker compose up -d --build
open http://localhost:3000   # the console
